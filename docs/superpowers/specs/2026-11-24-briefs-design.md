# 計畫 5：招募與機會頁設計

來源：`2026-11-22-ui-design.md` §4（我的招募、機會）、§5.4、§6（品牌刊登招募表單），以及 `plans/2026-11-22-foundation-followups.md` 的「4. 創作者廣場、5. 招募與機會頁」。視覺沿用 `2026-11-24-ui-refresh-design.md`；選項、驗證、圖片上傳的寫法沿用計畫 3、4。

## 使用者決定（2026-11-24）

| 題目 | 決定 |
|---|---|
| 未審核創作者 | 可以瀏覽機會、看詳情，但不能報名。報名按鈕停用，顯示「審核通過後即可報名」。資料庫也要擋。 |
| 截止日 | 過了截止日就自動視為結束：機會頁不顯示、不能報名（資料庫擋）。截止日當天（台灣時間）還可以報名。過了截止日後，品牌仍然可以查看報名者，也可以錄取或婉拒。 |
| 刪除招募 | 只有草稿能刪除。發佈後只能「關閉」，報名紀錄會保留。 |
| 錄取 | 這次只標記「已錄取」，雙方都看得到。建立對話和合作案留到計畫 6、7，那時再接上錄取。 |

「今天」一律用台灣時間（`Asia/Taipei`）的日期。招募在 `deadline >= 台灣今天` 時仍算開放。

## 招募狀態

`draft`（草稿）→ `open`（發佈中）→ `closed`（已關閉）。另外，畫面會把「`open` 但已經過了截止日」顯示成「已截止」。這個狀態不寫進資料庫，由日期算出來。

- 草稿：可以編輯、刪除、發佈。
- 發佈中：可以編輯（所有欄位，截止日不能早於今天）、可以關閉。不能改回草稿。
- 已關閉或已截止：不能編輯，也不能重新開啟（YAGNI；需要的話再開一則新的）。

## 品牌端

導覽列「我的招募」改成 `/brand/briefs`。

### `/brand/briefs`：我的招募列表

- 分頁標籤：發佈中、草稿、已結束（已關閉加上已截止）。
- 每列顯示：案名、狀態、截止日（剩幾天）、報名人數（其中待處理幾位）、建立日期。
- 右上角「刊登招募」按鈕。
- 空狀態：「還沒有招募，刊登第一則吧」。

### `/brand/briefs/new` 與 `/brand/briefs/[id]/edit`：分步驟表單（4 步）

1. **合作內容**：案名（1–60 字）、說明（1–2000 字）、合作形式（多選 `COLLAB_TYPES`，至少 1 個）、封面圖（選填，沒有時顯示品牌 Logo）。
2. **創作者條件**：內容領域（多選 `CATEGORIES`，0–5 個，0 代表不限）、最低粉絲數（0 代表不限）、地區（`REGIONS` 單選或不限）。
3. **酬勞與期限**：
   - 預算下限與上限（選填，0 到 10,000,000 的整數，上限必須 ≥ 下限；只填一個也可以）。
   - 是否提供產品（勾選）。
   - 預算和產品至少要有一項。
   - 截止日：今天到 90 天內。
4. **預覽並發佈**：用創作者看到的詳情頁樣式預覽，可以選「存成草稿」或「發佈」。

規則：
- 每一步按「下一步」時先在前端驗證，最後送出時伺服器再完整驗證一次。
- 「存成草稿」在任何一步都可以按，草稿只檢查格式，不檢查必填。
- 步驟用網址參數 `?step=1..4` 表示，重新整理後停在同一步。尚未儲存的內容只存在畫面上，重新整理後會遺失。存了草稿的話，會從資料庫讀回來。

### `/brand/briefs/[id]`：招募詳情與報名者

- 上方：招募摘要、狀態、截止日，以及按鈕（編輯、發佈、關閉、刪除草稿）。
  - 關閉和刪除前要先確認。確認用頁面內的確認區塊，不要用瀏覽器的 `confirm()`。
- 報名者列表：頭像、名稱（連到 `/c/<handle>`）、粉絲數、互動率、地區、報名留言、提出的報價（沒有就顯示「依招募預算」）、報名時間、狀態。
- 待處理的報名者有「錄取」和「婉拒」兩個按鈕。錄取或婉拒後不能再改（YAGNI）。
- 篩選：全部、待處理、已錄取、已婉拒。
- 只有招募主本人看得到。別人用網址打開時顯示 404。

## 創作者端

### `/creator`：機會（取代目前的「即將推出」）

- 頂部篩選標籤，一次只選一個：
  - **適合我**（預設）
  - 全部
  - 各內容領域
  - 現金（`budget_max_twd > 0` 或 `budget_min_twd > 0`）
  - 互惠（`includes_product`）
- 另一個分頁「我的報名」，列出自己報名過的招募和狀態（待回覆、已錄取、未錄取、已撤回）。
- 只列出開放中、還沒截止的招募，依截止日由近到遠排序，一次 20 則，底部「載入更多」。
- **卡片**（§5.4）：
  - 封面圖（沒有時顯示品牌 Logo 或品牌名稱首字）。
  - 品牌 Logo、品牌名稱、案名、合作形式。
  - **酬勞**（主色、最醒目）：「NT$5,000–20,000」「NT$5,000 起」「最高 NT$20,000」「產品互惠 + NT$3,000 起」「產品互惠」。
  - **「✓ 符合你的條件」**：粉絲數 ≥ 門檻；地區不限或相同；內容領域不限或有交集；合作形式和創作者的 `collab_types` 有交集（創作者沒填時不檢查這項）。
  - 門檻、地區、已報名人數、剩餘天數（「今天截止」「剩 3 天」）。
  - 已報名過的卡片顯示「已報名」。
- 「適合我」就是只列出符合條件的招募。沒有結果時顯示「目前沒有完全符合的招募，看看全部吧」，並提供切到「全部」的連結。

### `/creator/briefs/[id]`：招募詳情

- 內容：封面、品牌資訊、案名、說明、合作形式、條件，以及哪幾項符合、哪幾項不符合、酬勞、截止日、已報名人數。
- 底部固定「報名」按鈕（手機）；桌面版放在右欄。
  - 未審核：按鈕停用，顯示「審核通過後即可報名」。
  - 已報名：顯示目前狀態。待回覆時可以「撤回報名」，撤回後不能再報名同一則（YAGNI）。
  - 已截止或已關閉：顯示「已結束」，但還是可以看詳情。這樣創作者從「我的報名」點進來時看得到內容。
- 報名表單（同一頁展開）：
  - 給品牌的話，選填，最多 500 字。
  - 提出不同的報價，選填，0 到 10,000,000 的整數。
  - 送出後顯示「已報名」。
- 不符合條件也可以報名，但要先顯示提醒「你的條件不完全符合，仍要報名嗎？」。這是給品牌的參考，不是硬性限制。
- 草稿和別人看不到的招募，顯示 404。

## 資料層

### 調整 `briefs`

- `cover_url` 改名為 `cover_path`，比照 `brand_profiles.logo_path`：
  - 值是 null，或 `<brand_id>/cover-<檔名>`，用 CHECK 限制格式。
  - 改名前先確認正式資料庫裡沒有招募資料。目前沒有任何寫入招募的程式，所以應該是 0 筆。migration 開頭要寫一段檢查，萬一有資料就停下來。
- 新增 `published_at timestamptz`。
- CHECK 限制：
  - 案名 1–60 字，說明 1–2000 字。
  - 合作形式 ≤ 6 個、每個 ≤ 20 字；內容領域 ≤ 5 個、每個 ≤ 30 字；地區 ≤ 30 字。
  - 預算 ≤ 10,000,000。
  - 草稿以外的招募，合作形式至少 1 個，並且有預算或產品。
  - 文字要經過 `clean_text` 處理，並拒絕 bidi 字元，跟現有函式一致。
- 索引：`briefs(status, deadline)`、`briefs(brand_id, created_at desc)`、`brief_applications(creator_id, created_at desc)`、`brief_applications(brief_id, status)`。

### 寫入一律用 definer 函式

收回 authenticated 對 `briefs` 的直接 insert、update、delete，並拿掉 `briefs_write_own`。同時收回 `brief_applications` 的直接 insert，並拿掉 `brief_applications_insert_self`。anon 的所有權限也收回（目前 grant 檔給了 anon，這是之前的疏漏）。

每個函式都要設定 `set search_path = ''`，並先檢查呼叫者的身分：

| 函式 | 誰可以呼叫 | 規則 |
|---|---|---|
| `save_brief(p_id uuid null, …欄位…, p_publish boolean) returns uuid` | 品牌 | `p_id` 是 null 時新增。草稿或發佈中的招募才能修改，而且必須是自己的。`p_publish = true` 時檢查完整必填，並設定 `published_at`。截止日要在今天到 90 天之間。封面路徑必須屬於自己。 |
| `close_brief(p_id)` | 品牌（招募主） | `open` 才能改成 `closed`。 |
| `delete_brief(p_id)` | 品牌（招募主） | 只能刪除 `draft`。 |
| `apply_to_brief(p_brief_id, p_message, p_proposed_price) returns uuid` | 創作者 | 創作者必須已審核（42501「審核通過後即可報名」）。招募必須是 `open` 而且還沒截止。不能重複報名（23505）。留言最多 500 字。 |
| `withdraw_application(p_id)` | 創作者（本人） | `applied` 才能改成 `withdrawn`。 |
| `decide_application(p_id, p_accept boolean)` | 品牌（招募主） | `applied` 才能改成 `accepted` 或 `rejected`。招募關閉或截止後也可以操作。 |

讀取：

- `briefs_select`：
  - 創作者讀得到「`open` 而且還沒截止」的招募。
  - 招募主讀得到自己的全部招募。
  - 創作者讀得到自己報名過的招募（任何狀態，「我的報名」需要）。
  - 管理員讀得到全部。
  - 品牌看不到其他品牌的招募（YAGNI）。
  - 「是否截止」要用台灣時間的日期計算，寫成一個 `stable` 的 helper 函式，`today_tw()`。
- 報名人數：創作者讀不到別人的報名，所以要用 definer 函式 `brief_application_counts(p_ids uuid[])` 回傳人數，只算 `applied` 和 `accepted`。創作者呼叫時，只回傳他看得到的招募。
- 機會列表：用 definer 函式 `list_opportunities(p_filter text, p_category text, p_limit, p_offset)`，只給創作者呼叫。回傳招募欄位、品牌名稱、品牌 Logo 路徑、報名人數、`is_match`、`has_applied`、`total_count`。
  - `is_match` 的規則跟上面「符合你的條件」完全一樣，寫在 SQL 裡，前端只負責顯示。
  - 詳情頁要顯示哪幾項符合，所以函式要另外回傳四個布林欄位：粉絲數、地區、內容領域、合作形式各是否符合。
- 報名者列表：品牌用一般 select 讀 `brief_applications`（受 RLS 限制）。創作者的公開資料要經過 definer 函式 `list_brief_applicants(p_brief_id)` 讀取，只給招募主呼叫，因為還沒審核或已停權的創作者，公開資料品牌讀不到。不過報名本來就只有已審核的創作者，回傳時照實帶出目前的狀態即可。

### 封面圖片

新的公開 bucket `brief-covers`：
- 5 MB，只接受 jpeg、png、webp。
- 只有品牌能寫入，而且只能寫在 `<uid>/cover-…`。
- 跟 `creator-media` 的做法相同，這次一開始就加上 update 和 delete 的 policy 與測試。

孤兒檔清理和其他 bucket 共用同一個排程（待辦）。

## 不在範圍內

- 錄取後建立對話和合作案（計畫 6、7）。
- 通知（Email 或站內）。
- 品牌之間互看招募。
- 重新開啟已關閉的招募。
- 修改錄取或婉拒的決定。
- 撤回後再報名。
- 管理員操作。
- 公開（未登入）的招募頁。

## 驗收

- **資料庫測試：**
  - 每個函式的身分、狀態、截止日（含台灣時間的邊界：截止日當天可以，隔天不行）、重複報名、未審核不能報名、別人的招募不能改。
  - RLS：創作者看不到草稿和別的品牌；品牌看不到別人的招募和報名。
  - 直接 insert、update、delete 被拒絕。
  - `is_match` 的四個條件各自正確。
  - 報名人數只算 `applied` 和 `accepted`。
  - bucket 的 policy，包括 update 和 delete。
  - migration 在已有招募資料時會停下來。
- 單元測試、lint、tsc、build 全部通過。
- **E2E**（本機，用測試快速登入，並用 SQL 建立種子資料），在 390 與 1280 截圖：
  1. 品牌照四步驟刊登：中途存草稿，重新整理後接著填，最後發佈。
  2. 創作者在「適合我」看到這則招募，有「符合你的條件」；看詳情、報名並附留言和報價。
  3. 未審核的創作者看得到，但不能報名。
  4. 品牌在詳情頁看到報名者，錄取一位、婉拒一位，創作者在「我的報名」看到結果。
  5. 創作者撤回報名。
  6. 品牌關閉招募後，機會頁不再顯示這則。
  7. 截止日過了，機會頁不顯示，但品牌仍然可以錄取。
  8. 刪除草稿。
