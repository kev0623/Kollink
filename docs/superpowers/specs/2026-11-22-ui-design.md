# Kollink UI 設計規格 — MVP

- 日期：2026-11-22
- 範圍：Phase 1 MVP 的介面設計（品牌端、創作者端、共用頁、管理後台）
- 背景：見 `PROJECT_BRIEF.md`（專案簡報）。整體架構參考小紅書「蒲公英」，但依台灣市場調整。
- 預定技術：Next.js（App Router）+ Tailwind CSS + shadcn/ui。

---

## 1. 設計原則

1. **兩端並重**：品牌（付費方）和創作者（供給方）同樣重要，但介面重點不同。
2. **品牌端以電腦版優先，創作者端以手機版優先**（對應蒲公英的「品牌用 PC、博主用 App」）。我們沒有 App，創作者端做成手機版優先的 RWD 網頁，之後可以包成 PWA。
3. **任何時候都知道「現在輪到誰、要按什麼」**：每個合作狀態只有一個主要按鈕。
4. **讓人不想私下交易**：報價需要登入才看得到；評價、完成案數、準時率只存在平台上；款項託管的狀態隨時看得到。

## 2. 視覺風格

調性：**B 的結構和可信度（像 Notion / Linear）+ A 的溫度（像小紅書 / Pinterest）**。品類尚未決定，先用中性設計，主色之後可以調整。

| Token | 值 | 用途 |
|---|---|---|
| `--color-primary` | `#E8684A`（珊瑚橘） | 主要按鈕、目前步驟、價格 |
| `--color-primary-soft` | `#FCE9E2` | 目前步驟的光暈、自己的訊息泡泡 |
| `--color-bg` | `#FBF7F2`（米白） | 頁面底色 |
| `--color-surface` | `#FFFFFF` | 卡片 |
| `--color-ink` | `#2B2522` | 主要文字 |
| `--color-muted` | `#8A7F78` | 次要文字 |
| `--color-line` | `#EFE6DE` | 分隔線、外框 |
| `--color-success` | `#3E8E6A`（底色 `#E6F2EC`） | 「符合你的條件」、完成狀態 |

- 字體：Noto Sans TC（思源黑體），系統字體作為備用。
- 圓角：卡片 12px、按鈕 8–10px、標籤 999px（膠囊形）。
- 陰影：只用很淡的 `0 1px 3px rgba(60,40,30,.07)`，不做厚重陰影。
- 主色用於「要你做事」或「錢」的地方，不要大面積使用。
- 暗色模式：MVP 不做。

## 3. 帳號與身分

- 註冊時選擇「品牌」或「創作者」，一個帳號只有一種身分（MVP）。
- 資料表把 `users` 和 `brand_profiles` / `creator_profiles` 分開存，以後可以開放一人兩種身分（像 Airbnb 的切換），或讓一個品牌有多位成員，不必重做資料庫。

## 4. 資訊架構

### 公開頁（不用登入）
| 頁面 | 路徑 | 說明 |
|---|---|---|
| 首頁 | `/` | 兩個入口：「我是品牌」「我是創作者」 |
| 創作者公開檔案頁 | `/c/[handle]` | 可分享、可被 Google 搜尋到；報價需要品牌登入後才看得到 |
| 註冊 / 登入 | `/signup`、`/login` | 註冊時選擇身分 |

### 品牌端（電腦版優先，左側導覽列）
| 頁面 | 說明 |
|---|---|
| 創作者廣場 | 篩選 + 混合卡片，可切換成列表（見 5.1） |
| 創作者詳情 → 發出邀約 | 定制合作：直接邀請某位創作者 |
| 我的招募 | 刊登需求（brief）、查看報名的創作者、挑選人選 |
| 合作案 | 列表 + 詳情頁（見 5.2） |
| 訊息、付款與發票、設定 | 標準頁面 |

### 創作者端（手機版優先，底部 5 個分頁）
| 分頁 | 說明 |
|---|---|
| 機會 | 品牌招募列表 → 報名（見 5.4） |
| 合作 | 收到的邀約（接受 / 婉拒）、進行中的案子、交稿 |
| 訊息 | 全部對話 |
| 收入 | 撥款紀錄 |
| 我的 | 編輯檔案與報價、一鍵複製分享連結 |

在電腦上，創作者端的底部分頁改成左側導覽列，項目相同。

### 管理後台（只有平台管理員看得到）
`/admin`：創作者審核、合作案總覽、撥款 / 退款、違規訊息列表。一般資料的查看和修改直接用 Supabase Table Editor；**撥款、退款、停權一定要透過後台頁面操作**，讓系統呼叫金流 API 並寫入 audit log。

## 5. 關鍵畫面

### 5.1 品牌端：創作者廣場（決定：C 混合卡片 + 切換）
- 左側是篩選欄：風格標籤、粉絲數、互動率、報價區間、地區、合作類型。
- 主區預設是**卡片模式**，一排 2–3 張。每張卡片包含：
  - 三張近期作品縮圖（並排）
  - 頭像、名稱、地區、內容領域、收藏 ♡
  - 粉絲數、互動率、**起價**（主色）
  - 2–3 個風格或合作類型標籤
- 右上角可切換到**列表模式**：一列一位創作者，欄位包含創作者、粉絲數、互動率、貼文報價、地區、查看，可依欄位排序。等之後串接 Meta API、有真實數據，再擴充列表欄位（例如閱讀中位數）。
- 使用者選擇的模式記在 localStorage。

### 5.2 合作案詳情頁（決定：A 上下排列，兩端共用）
由上到下：
1. **標題區**：「創作者 × 案名」、合作內容、金額與託管狀態（例：NT$4,500 已託管）、案號。
2. **進度條（7 步）**：邀約 → 確認 → 付款託管 → 交稿 → 審核 → 發佈 → 撥款。已完成的步驟用淡主色，目前步驟用主色加光暈，未來步驟用灰色。
3. **「現在要做什麼」卡片**：有主色外框。
   - 輪到自己時，顯示「輪到你：○○」、說明、期限，以及主要 / 次要按鈕（例：審核階段為「通過」/「要求修改」）和相關檔案縮圖。
   - 輪到對方時，顯示「等對方○○」和最晚回覆日，並明確告訴使用者「你不用做任何事」。
4. **對話區**：本案的訊息和系統事件（例：「11/25 小美已交稿」），底部是輸入框。

手機版：進度條縮成「目前狀態名稱 + 第 N / 7 步」加一條進度線；其他區塊由上而下排列，順序相同。

**每個狀態的主要動作**

下表的「目前步驟」是指進度條上正在進行、還沒完成的那一步。

| 目前步驟 | 輪到誰 | 主要按鈕 | 次要按鈕 | 完成後 |
|---|---|---|---|---|
| 邀約 | 創作者 | 接受 | 婉拒 | → 確認 |
| 確認 | 品牌 | 確認並付款 | 取消 | 付款完成 → 付款託管 |
| 付款託管 | 平台 | （等金流通知，自動完成） | — | → 交稿 |
| 交稿 | 創作者 | 上傳稿件 | — | → 審核 |
| 審核 | 品牌 | 通過 | 要求修改（必填修改說明） | 通過 → 發佈；要求修改 → 回到交稿 |
| 發佈 | 創作者 | 填入貼文連結 | — | → 撥款 |
| 撥款 | 平台 | （系統處理，雙方只能看狀態） | — | 結案 |

**逾期規則**：品牌在創作者交稿後 **3 天**內沒有審核，系統自動通過。這條規則要寫進服務條款，並在卡片上顯示倒數。

### 5.3 創作者公開檔案頁 `/c/[handle]`（決定：B 合作提案風格）
手機版優先，由上到下：
1. 頭像、名稱、地區、內容領域，以及**平台評分 ★、完成案數、準時率**
2. 三項數據：IG 粉絲、互動率、主要受眾年齡
3. 風格標籤
4. 6 張作品（3×2 網格）
5. **想接的合作**：IG 貼文、Reels、限動、產品互惠等
6. **報價方案**：沒有登入或不是品牌身分時，顯示鎖定區塊「🔒 品牌登入後可查看報價」，並提供登入連結
7. **合作過的品牌**：品牌 logo 加上最新一則評價
8. 固定在底部的「邀請合作」按鈕（沒有登入時，點了會先導向品牌註冊）

電腦版：左欄放 1–3，右欄放 4–7，「邀請合作」固定在右欄頂部。
SEO：頁面用伺服器端渲染（SSR），並設定 Open Graph 圖片（頭像 + 名稱 + 數據），貼到 LINE 或 IG 時會顯示預覽卡片。

### 5.4 創作者端：機會（決定：A 大卡片）
- 頂部有篩選標籤，預設是「適合我」，其他還有「全部」、品類、「現金」、「互惠」。
- 每則招募一張卡片：
  - 品牌形象圖（封面）
  - 品牌 logo、品牌名稱、案名與合作形式
  - **酬勞（主色、最醒目）**，可以是金額區間或「產品互惠 + 金額」
  - **「✓ 符合你的條件」標籤**：依創作者檔案比對粉絲門檻、地區、合作類型
  - 門檻、地區、已報名人數、剩餘天數
- 點進去是招募詳情頁，底部固定一個「報名」按鈕。報名時可以附上一段話，也可以提出不同的報價。

## 6. 標準頁面（沿用上述風格，不另外畫稿）
- **首頁**：主標語、兩個身分入口（各一張大卡片）、精選創作者（3–6 張 5.1 的卡片）、「怎麼運作」三步驟、計費說明、頁尾。
- **註冊**：第一步選擇身分（兩張大卡片）；第二步填寫 Email 或用 Google 登入；第三步完成基本檔案（創作者填 IG 帳號、粉絲數、地區、風格；品牌填品牌名稱、統編和產業）。
- **品牌刊登招募表單**：使用分步驟表單，共 4 步：合作內容 → 創作者條件 → 酬勞與期限 → 預覽並發佈。
- **訊息**：左邊是對話列表，右邊是對話內容；手機版分成兩頁。會自動偵測聯絡方式：輸入電話、Email、LINE ID 或外部連結時，送出前會先跳出提醒，送出後在後台標記。
- **後台**：表格為主，不講究視覺，使用 shadcn/ui 的預設樣式。

## 7. 共用元件清單
`Button`（primary / secondary / ghost）、`Chip`（標籤）、`CreatorCard`、`CreatorRow`、`OpportunityCard`、`CollabStepper`（電腦版 / 手機版兩種形式）、`ActionCard`（「現在要做什麼」）、`ChatThread`、`PriceLock`、`RatingSummary`、`BottomTabBar`、`SideNav`。

## 8. 不在本次範圍
- 共創合作（由平台推薦一組創作者、按成效計費）、加價推曝光、合作廣告串接
- 一個帳號兩種身分、品牌多成員
- Meta API 的真實數據（MVP 的數據由創作者自己填，畫面上要標示「創作者自行提供」）
- 暗色模式、多語系、原生 App
