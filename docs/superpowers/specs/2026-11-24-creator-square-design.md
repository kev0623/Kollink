## 誰看得到

## 頁面

### 篩選欄

桌面版放在左側，手機版收進「篩選」按鈕打開的抽屜。由上到下：

1. 關鍵字（顯示名稱、handle、IG 帳號，不分大小寫的部分比對）。
2. 只看收藏（開關）。
3. 內容領域（多選，沿用 `CATEGORIES`）。
4. 風格標籤（多選。選項取自目前已審核創作者用過的標籤，依使用次數排序，最多顯示 20 個）。
5. 粉絲數區間：不限、1 千以下、1 千到 1 萬、1 萬到 10 萬、10 萬以上。
6. 互動率：不限、≥ 1%、≥ 3%、≥ 5%。
7. 起價區間：不限、5 千以下、5 千到 2 萬、2 萬以上（以該創作者所有報價中的最低價計算；沒有報價的人在選了區間時不列出）。
8. 地區（多選，沿用 `REGIONS`）。
9. 合作類型（多選，沿用 `COLLAB_TYPES`）。
10. 「清除篩選」。

多選欄位：同一欄位內符合任一個即可（OR），不同欄位之間要全部符合（AND）。
篩選條件不在白名單裡時（例如舊資料或手改網址），要能正常運作，不能報錯（followups：「搜尋與篩選必須能容忍清單以外的值」）。

### 結果區

- 右上角：結果數量、排序選單、卡片和列表的切換。使用者選的模式記在 localStorage，讀寫都要包 try/catch；讀不到時預設卡片模式。
- **卡片模式**（桌面一排 3 張、平板 2 張、手機 1 張）：
  - 最多三張作品縮圖並排；沒有作品時顯示淡灰底和名字首字。
  - 頭像、名稱、地區、內容領域、♡。
  - 粉絲數、互動率、**起價**（主色、粗體；沒有報價時顯示「洽談」）。
  - 最多 3 個標籤，風格標籤優先，不夠再用合作類型補。
  - 整張卡片連到 `/c/<handle>`；點 ♡ 不會觸發跳頁。
- **列表模式**：一列一位創作者，欄位是創作者（頭像加名稱）、粉絲數、互動率、貼文報價（`IG 貼文` 的價格，沒有就顯示「—」）、地區、查看。點欄位標題會切換排序，對應上面的四種排序；只有這四種可排序，其他欄位標題不可點。手機版的列表可以左右捲動，但整頁不能出現水平捲軸。
- 「載入更多」：還有下一批時才顯示。按下後保留已顯示的結果，接著顯示下一批。
- 空狀態：
  - 沒有任何符合的創作者：顯示「找不到符合條件的創作者」和「清除篩選」。
  - 開了「只看收藏」但沒有收藏：顯示「還沒有收藏的創作者」。

### 收藏

- ♡ 可以按在廣場卡片、列表列，以及公開頁 `/c/<handle>`。公開頁只有品牌看得到 ♡，位置在名稱旁邊。
- 按下後畫面先切換（樂觀更新），失敗時切回原本狀態並顯示錯誤。
- 未登入或不是品牌時，不顯示 ♡。

## 資料層

### 收藏資料表 `creator_favorites`

`brand_id uuid → brand_profiles.user_id on delete cascade`、`creator_id uuid → creator_profiles.user_id on delete cascade`、`created_at timestamptz default now()`、`primary key (brand_id, creator_id)`。

- RLS：品牌只能讀、新增、刪除自己的收藏（`brand_id = auth.uid()`），而且新增時 `my_role() = 'brand'`。不開放 UPDATE。
- 在 migration 裡明確寫 `grant`。service_role 只給 SELECT。
- 收藏未審核創作者：資料庫允許（審核狀態可能會變），但廣場只列出已審核的人。

### 搜尋函式 `search_creators(...)`

使用 security definer 函式（`set search_path = ''`）：
- 呼叫者必須是品牌，否則 42501。
- 只回傳已審核的創作者。

參數對應上面的篩選與排序，加上 `p_limit`（最多 48）與 `p_offset`。

每一列回傳：
- `user_id`、`handle`、`display_name`、`avatar_path`、`region`、`categories`、`style_tags`、`collab_types`、`follower_count`、`engagement_rate`
- `min_price`：最低報價，沒有報價時是 null。
- `post_price`：`IG 貼文` 的報價。
- `portfolio_paths`：依 position 排序的前三張作品路徑。
- `is_favorite`、`created_at`。

另外回傳符合條件的總數，可以用另一個 `count_creators` 函式，或用 window 函式算，由實作計畫決定。

規則：
- 關鍵字要跳脫 `%`、`_`、`\`。
- 用 `ilike` 部分比對。
- 排序要有穩定的次要鍵（`created_at desc, user_id`），這樣分頁不會重複或漏掉。
- 報價會出現在結果裡，所以只能給品牌呼叫。這符合現有規則（報價只給品牌看）。

`popular_style_tags()`：只給品牌呼叫，回傳已審核創作者用過的風格標籤和使用次數，最多 20 個。

### 索引（followups 計畫 4 的項目）

- `creator_profiles(status, created_at desc)`
- `categories`、`style_tags`、`collab_types` 的 GIN 索引
- `creator_rates(creator_id, price_twd)`
- `creator_favorites(brand_id, created_at desc)`

招募、對話、合作案的索引留到計畫 5、6，跟用到它們的查詢一起加。

## 驗收

- **資料庫測試：**
  - 非品牌（anon、創作者、沒有 profile 的使用者）呼叫 `search_creators` 被拒絕。
  - 只回傳已審核的創作者。
  - 每個篩選條件各自正確，組合時是 AND、多選欄位內是 OR。
  - 關鍵字裡的 `%`、`_` 照字面比對。
  - 四種排序和分頁穩定，不會重複或漏掉。
  - `is_favorite` 正確。
  - 收藏的 RLS：不能讀或改別人的收藏，創作者不能收藏。
- 單元測試、lint、tsc、build 全部通過。
- **E2E：** 在本機建立至少 8 位已審核創作者，資料各不相同。以品牌身分完成以下流程，並在 390 與 1280 截圖：
  1. 篩選、關鍵字搜尋、排序。
  2. 切換卡片和列表，重新整理後模式還在。
  3. 載入更多。
  4. 收藏，再開「只看收藏」。
  5. 在公開頁收藏或取消收藏，回到廣場確認狀態一致。
  6. 用分享出去的篩選網址重新開啟，結果一樣。
