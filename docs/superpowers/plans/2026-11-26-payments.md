# Kollink 綠界金流 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 品牌在合作案詳情（等待付款）選信用卡或 ATM 轉帳、按「確認並付款」後整頁轉到綠界付款頁；綠界的伺服器通知（ReturnURL）驗簽後把合作案推進到交稿，ATM 的取號通知（PaymentInfoURL）把銀行代碼、虛擬帳號、期限顯示給品牌；金額不符等異常不報錯、記錄下來給管理員；退款只做記錄（README 附 SQL）。現在用綠界公開的測試環境，之後只換環境變數就能收真錢；環境變數不齊時按鈕停用。

**Architecture:** 一個 migration `20261127000100_payment_orders.sql`：`payments` 新欄位（方式、環境、ATM 資訊、退款）與欄位權限（authenticated 讀不到 `raw_notify`）、`payment_anomalies`、`create_payment_order`（品牌自己的 client 呼叫，資料庫產生付款單編號）、`record_payment_success` 加 `p_env` 並改成異常不報錯、`record_payment_info`、`resolve_payment_refund`、`resolve_payment_anomaly`。TS 端：`src/lib/payments/` 放設定（`config.ts`，server-only）、限額、綠界表單（`checkout.ts`）、通知欄位白名單、兩種通知的純處理函式、付款摘要；三個 route（`notify`、`payment-info`、`result`）；品牌的 Server Action `startPaymentAction` 建單並回傳簽好的表單，client 元件渲染隱藏表單後 `submit()`。付款狀態只相信伺服器通知；瀏覽器回來的 `result` route 只做導向。

**Tech Stack:** Next.js 16.4.6（App Router、`cacheComponents`、Server Actions、`proxy.ts`）、React 19.3、TypeScript、Tailwind v4、Supabase CLI 3.2（Postgres 17）、`@supabase/supabase-js` 2.119、pgTAP、Vitest（node 環境）、Node `crypto`（SHA256、`timingSafeEqual`）。

**Spec:** `docs/superpowers/specs/2026-11-26-payments-design.md`（含使用者決定、代替使用者做的決定、綠界文件連結；延後事項與既有決定見 `docs/superpowers/plans/2026-11-22-foundation-followups.md`）

## Global Constraints

- Next.js 16 與訓練資料不同：寫程式前先讀 `node_modules/next/dist/docs/` 對應文件（本計畫用到的已列在下方「設計決定」）。`middleware.ts` 已改名為 `proxy.ts`。
- `cacheComponents` 已開啟：讀 `cookies()`、`headers()`、`searchParams`、`params` 的元件必須在 `<Suspense>` 內。不可使用 `export const runtime`、`export const dynamic`。讀現在時間只能在 `requireRole()`（內部已 `await connection()`）之後；client 元件不自己算現在時間，由伺服器把 `nowMs` 當 prop 傳下去（`summarizePayments(rows, nowMs)` 是純函式）。Route handler 讀 `request` 本來就是請求時執行。
- 金鑰：`ECPAY_MERCHANT_ID`、`ECPAY_HASH_KEY`、`ECPAY_HASH_IV`、`ECPAY_ENV`、`SITE_URL` 只在伺服器端讀（`src/lib/payments/config.ts`，`import "server-only"`），絕不加 `NEXT_PUBLIC_`，也不能出現在回傳給瀏覽器的值裡（`startPaymentAction` 只回傳表單欄位與 `CheckMacValue`；畫面只拿 `paymentAvailability()` 的 `{ enabled, env }`）。`SUPABASE_SECRET_KEY` 只能出現在 import `server-only` 的檔案。
- 品牌建單一律用**品牌自己的** client（`src/lib/supabase/server.ts`）呼叫 `create_payment_order`，由資料庫檢查身分與狀態；`createAdminClient()`（service_role）只用在兩個綠界通知 route（伺服器對伺服器，沒有使用者）。
- 付款狀態只以綠界伺服器通知（`notify`）為準。`result` route（瀏覽器 POST）不讀內容、不改任何狀態。
- SQL 函式一律 `set search_path = ''`，物件名稱寫完整 schema；`RETURNS TABLE` 的 plpgsql 函式加 `#variable_conflict use_column`，欄位一律加表別名。
- 權限寫在 migration（followups「資料表權限寫在 migration」）：新資料表先 `revoke all ... from anon, authenticated, service_role` 再明確 `grant`；新函式先 `revoke execute ... from public, anon, authenticated, service_role` 再 `grant` 給需要的角色；內部 helper 不 grant 給任何 API 角色。
- 錯誤碼（TS 端只透過 `src/lib/collabs/errors.ts` 轉成中文）：身分 `42501`（`not authenticated`、`not collaboration brand`、`not admin`）；找不到 `P0002`（`collaboration not found`、`payment not found`、`anomaly not found`）；狀態 `55000`（`collaboration not awaiting payment`、`refund not required`、`anomaly already resolved`）；格式 `22023`（`invalid payment method`、`amount exceeds online payment limit`、`invalid payment info`、`invalid note`、`invalid env`、`amount is required`、`provider_trade_no is required`）；頻率 `54000`（`too many payment orders`）。
- 綠界通知回應一律純文字（`content-type: text/plain; charset=utf-8`），成功是 `1|OK`（大小寫與符號不能錯）。驗簽、MerchantID、格式錯誤回 400；資料庫錯誤與未設定回 500（綠界會重送）；其餘（成功、重複、需退款、異常、付款失敗、取號失敗、正式環境的模擬付款）一律 `1|OK`。
- 數字常數兩邊要一致：`PAYMENT_MAX_TWD = 200000`（TS `src/lib/payments/limits.ts` ↔ SQL `create_payment_order`）；raw 白名單（TS `NOTIFY_FIELDS` ↔ SQL `payment_raw_whitelist`，SQL 多一個 `source`）。兩邊的註解互相指向。
- 每個讀取使用者資料的頁面都要呼叫 `requireRole(...)`（layout 的 Gate 不算數）；Server Action 開頭 `requireRole("brand")`，參數一律當成 `unknown` 檢查（`isUuid`、`isPaymentMethod`）。`"use server"` 檔案只能 export async 函式（型別可以；字串常數不行）。
- `supabase gen types` 產生的型別把 `RETURNS TABLE` 欄位都標成非 null：一律自己定義欄位可為 null 的 Row 型別，`data` 先轉 `unknown` 再轉型。
- 送出按鈕：進行中一律 `disabled`。確認一律用頁面內的區塊（既有 `ConfirmAction`），不可用 `confirm()`。
- 介面文字為繁體中文；產品名稱只從 `src/lib/site.ts` 的 `SITE_NAME` 取得。
- 顏色只用 `src/app/globals.css` 的 token class（`bg-surface`、`bg-primary-soft`、`border-line`、`border-danger`、`text-ink`、`text-muted`、`text-danger`、`text-primary`、`bg-ink`、`text-on-ink`、`accent-ink`…）；圓角 `rounded-card`、`rounded-btn`。不可用 `text-white` 或色碼。手機 390 寬不可出現整頁水平捲軸（長字串加 `break-all`／`break-words`、`min-w-0`）。
- 不新增 npm 套件。E2E 用的 playwright-core 裝在 scratchpad，不加進專案。
- 只動**本機** Supabase：不可執行 `supabase link`、`db push --remote`、`supabase config push`，也不可連到正式專案或 Vercel 正式環境變數。
- 不可同時跑兩個 `next build`／`next dev`／`next start`（共用 `.next`）；只有 Task 7 會啟動伺服器（一個 dev server、port 3000），用完要關掉。
- 不可對綠界**正式**環境（`payment.ecpay.com.tw`）送任何表單。Task 7 只用測試環境（`payment-stage.ecpay.com.tw`）與公開的測試卡。
- 每個 task 結束時：`npm run lint && npm run typecheck && npm test` 全過；有動到 SQL 的 task 另跑 `npx supabase test db` 全過。畫面元件沒有單元測試環境（vitest 是 node 環境），由 typecheck、lint、Task 7 的 build 與 E2E 驗證。
- pgTAP fixture 一律寫在該測試檔自己的 transaction 裡（結尾 `rollback`），id 用本計畫專屬的前綴（`…0009xx`、`…00009…`），不能影響 `01`、`05` 這些會數列數的舊測試。
- Commit 訊息用中文寫「計畫 8 Task N：重點」，結尾加你所在環境指定的 Co-Authored-By 歸屬行（寫實際執行的模型）。
- 前置：Docker Desktop 已啟動，`npx supabase start` 已執行，`.env.local` 已設定（見 README「本機開發」）。每個 DB task 開始前先 `npx supabase migration up` 套用新 migration。

讀過的文件：
- 綠界：測試介接資訊 https://developers.ecpay.com.tw/2856/ 、產生訂單 https://developers.ecpay.com.tw/?p=2862 、信用卡 https://developers.ecpay.com.tw/?p=2866 、ATM https://developers.ecpay.com.tw/?p=2872 、付款結果通知 https://developers.ecpay.com.tw/?p=2878 、取號結果通知 https://developers.ecpay.com.tw/?p=2881 、檢查碼 https://developers.ecpay.com.tw/?p=2902 （重點整理在 spec「綠界文件」一節）
- `node_modules/next/dist/docs/01-app/02-guides/server-actions.md`（「Security」：action 是公開的 POST、內建 Origin／Host 比對；`redirect` 之後的程式不會執行）
- `node_modules/next/dist/docs/01-app/03-api-reference/03-file-conventions/route.md`（route handler 支援 `GET`／`POST`；`request.formData()` 讀表單）
- `node_modules/next/dist/docs/01-app/03-api-reference/03-file-conventions/proxy.md`（`config.matcher` 的負向前瞻排除路徑）
- `src/proxy.ts`、`src/lib/payments/ecpay.ts`（既有 CheckMacValue，已通過官方範例，不改）、`src/lib/payments/ecpay-notify.ts`、`src/app/api/payments/ecpay/notify/route.ts`、`src/app/api/dev/mark-paid/route.ts`、`src/app/api/cron/auto-approve/route.test.ts`（route 測試 mock 的寫法）

決定：
1. **一個 migration、一個新 pgTAP 檔**（`22_payment_orders.test.sql` 54 個），另改 `04_payments.test.sql` 三個斷言（找不到付款單、金額不符、付款單與報價不符：從「報錯」改成「回傳 `anomaly`」，總數 28 不變）。本計畫撰寫時已把 migration、新測試、改過的 `04`，以及其他 20 個既有測試檔，在本機 rollback 的 transaction 裡實際跑過，全部通過（`03` 44、`04` 28、`05` 122、`11` 138、`13` 37、`15` 22、`18` 51……）。本計畫的 TS 程式（Task 2–5）也在 scratchpad 的副本跑過 `tsc --noEmit`、`eslint`、`vitest`（66 個檔、609 個測試全過）；`next build` 沒跑過（Task 7 會跑）。
2. **付款單編號由資料庫產生**：`KL` + 台灣日期 `YYMMDD` + `gen_random_uuid()` 的前 12 位大寫十六進位 = 20 字（綠界上限 20、英數字）。測試商店 3002607 所有人共用，所以要夠亂。每次「確認並付款」都建新單，從不重送舊編號（綠界拒絕重複的 `MerchantTradeNo`）。
3. **建單權限**：`create_payment_order` grant 給 authenticated，內部用 `auth.uid()` 判斷是不是這個合作案的品牌（創作者 42501、第三方 P0002，與計畫 6 的 `submit_deliverables` 同一種寫法），金額一律取合作案報價。這樣 action 不需要 service_role。
4. **環境寫在付款成功時**：`provider_env` 不在建單時寫（呼叫者可以亂填），而是 `record_payment_success(…, p_env)` 由通知 route 依「驗證這份通知的金鑰」填入。本機按鈕與 README 人工 SQL 用舊的四參數呼叫，`provider_env` 是 null。
5. **異常不報錯**：綠界同一份通知只重送 4 次。原本金額不符會 `raise`，等於什麼都沒留下。改成 `record_payment_anomaly`（唯一索引去重，第一次另寫 audit `payment_anomaly`、`raise warning`），回傳 `anomaly`，route 回 `1|OK` 並 `console.error`。付款單與合作案報價不符（只可能是人工建錯單）也一樣，付款單維持 pending。
6. **欄位權限**：authenticated 對 `payments` 改成欄位層級的 SELECT（不含 `raw_notify`、`created_by`、`refund_note`）。所以讀取付款單一律列出欄位（`PAYMENT_COLUMNS`），不能 `select("*")`。`count(*)` 仍然可以。
7. **模擬付款**：`SimulatePaid=1` 在 `ECPAY_ENV=prod` 一律忽略；stage 照常記錄（綠界測試環境的 ATM 只能用廠商後台的模擬付款）。
8. **信用卡回到站上**：`OrderResultURL = SITE_URL/api/payments/ecpay/result?c=<合作案>`。綠界從瀏覽器跨站 POST，SameSite=Lax 的 cookie 不會帶，所以 route 只回 303 到 `/brand/collabs/<id>`（之後的 GET 會帶 cookie）。`proxy.ts` 的 matcher 改成排除整個 `api/payments/ecpay/`。ATM 不支援 OrderResultURL，用 ClientBackURL。
9. **商品名稱不放使用者輸入**：`ItemName = "Kollink 合作案 <案號>"`、`TradeDesc = "Kollink 合作案款項"`。案名可能有 emoji、`#`（綠界的多商品分隔），綠界文件提醒特殊字元與截斷會造成 CheckMacValue 錯誤。
10. **自動送出表單**：action 回傳 `{ action, fields }` 後，client 元件把它存進 state 渲染成隱藏 `<form method="post" acceptCharset="UTF-8">`，`useEffect` 裡 `formRef.current.submit()`（`submit()` 不會觸發 React 的 onSubmit，也不會被 React 19 的 form action 攔下，因為 `action` 是字串網址）。
11. **畫面的付款摘要**：`loadCollabDetail` 多讀最近 20 張付款單（使用者自己的 client，RLS 只給參與者與管理員）；`summarizePayments(rows, nowMs)` 算出「測試付款」「ATM 待繳」（最新一張、已取號、`atm_expire_date >= 台灣今天`）「信用卡確認中」（最新一張、30 分鐘內）「需退款」。
12. **E2E 怎麼處理 ReturnURL**：綠界的伺服器連不到 localhost。Task 7 在綠界測試環境用測試卡真的付一次，用 Playwright 攔下綠界讓瀏覽器 POST 給 OrderResultURL 的原文（由綠界簽章），(a) 存成 fixture、單元測試用公開測試金鑰驗簽（followups 要求的「真實沙盒樣本」），(b) 原封不動重送到本機 `notify`，走完整條路。ATM 的取號與付款通知則用 scratchpad 的簽章腳本（啟動時先用綠界官方範例自我檢查）簽一份送到本機。合併後在正式站（測試模式）再做一次真的 ReturnURL 煙霧測試（README）。
13. **README 的人工 SQL**：保留「人工標記已付款」與「撥款」到計畫 9，前者標明只在「超過線上付款上限」「綠界通知遺失」時使用，而且呼叫 `record_payment_success` 的那一步加上 `p.merchant_trade_no like 'MAN%'`（原本會把該合作案**所有** pending 的單都標成已付款，線上付款上線後會誤標品牌放棄的綠界單）；撥款 SQL 加檢查，拒絕撥款給測試付款（`provider_env = 'stage'`）。新增「需退款的款項」「處理退款」「付款異常」「處理異常」四段 SQL。

```sql
  merchant_trade_no text not null check (char_length(merchant_trade_no) <= 64),

  collaboration_id uuid references public.collaborations (id),

  on public.payment_anomalies (source, kind, merchant_trade_no, provider_trade_no);

--    不保存 card4no、card6no、ATMAccNo 等付款人資料，即使綠界之後多傳了欄位。
create function public.payment_raw_whitelist(p jsonb) returns jsonb
language sql immutable set search_path = '' as $$
  select coalesce(jsonb_object_agg(e.key, e.value), '{}'::jsonb)
    from jsonb_each(case when jsonb_typeof(p) = 'object' then p else '{}'::jsonb end) e
   where e.key in ('MerchantID', 'MerchantTradeNo', 'StoreID', 'RtnCode', 'RtnMsg', 'TradeNo', 'TradeAmt',
                   'PaymentDate', 'PaymentType', 'PaymentTypeChargeFee', 'TradeDate', 'SimulatePaid',
                   'BankCode', 'vAccount', 'ExpireDate', 'source');
$$;
revoke execute on function public.payment_raw_whitelist(jsonb) from public, anon, authenticated, service_role;

create function public.record_payment_anomaly(
  p_source text, p_kind text, p_merchant_trade_no text, p_provider_trade_no text,
  p_payment_id uuid, p_collab_id uuid, p_expected integer, p_received integer, p_raw jsonb
) returns void
language plpgsql security definer set search_path = '' as $$
declare
  v_id bigint;
  v_status public.collab_status;
begin
  insert into public.payment_anomalies
    (source, kind, merchant_trade_no, provider_trade_no, payment_id, collaboration_id,
     expected_amount_twd, received_amount_twd, raw)
  values
    (p_source, p_kind, left(coalesce(p_merchant_trade_no, ''), 64), left(coalesce(p_provider_trade_no, ''), 64),
     p_payment_id, p_collab_id, p_expected, p_received, public.payment_raw_whitelist(p_raw))
  on conflict (source, kind, merchant_trade_no, provider_trade_no) do nothing
  returning id into v_id;

  if v_id is not null and p_collab_id is not null then
    select c.status into v_status from public.collaborations c where c.id = p_collab_id;
    insert into public.audit_logs
      (collaboration_id, actor_id, actor_kind, action, from_status, to_status, note)
    values
      (p_collab_id, null, 'system', 'payment_anomaly', v_status, v_status,
       format('%s (%s): expected %s, got %s', p_kind, p_source, p_expected, p_received));
  end if;
  raise warning 'payment anomaly: % % %', p_kind, p_source, left(coalesce(p_merchant_trade_no, ''), 64);
end;
$$;
revoke execute on function public.record_payment_anomaly(text, text, text, text, uuid, uuid, integer, integer, jsonb)
  from public, anon, authenticated, service_role;

-- 5. 建單：品牌以自己的 client 呼叫。檢查身分、狀態、金額上限、頻率；付款單編號由資料庫產生。
--    金額一律取合作案報價（呼叫者不能指定）。上限 200000 與 src/lib/payments/limits.ts 的 PAYMENT_MAX_TWD 相同。
create function public.create_payment_order(p_collab_id uuid, p_method text)
returns table (merchant_trade_no text, amount_twd integer, created_at timestamptz)
language plpgsql security definer set search_path = '' as $$
#variable_conflict use_column
declare
  v_uid uuid := auth.uid();
  c public.collaborations%rowtype;
  v_no text;
  v_recent integer;
begin
  if v_uid is null then
    raise exception 'not authenticated' using errcode = '42501';
  end if;
  if p_method is null or p_method not in ('credit', 'atm') then
    raise exception 'invalid payment method' using errcode = '22023';
  end if;
  select * into c from public.collaborations where id = p_collab_id for update;
  if not found or (c.brand_id <> v_uid and c.creator_id <> v_uid) then
    raise exception 'collaboration not found' using errcode = 'P0002';
  end if;
  if c.brand_id <> v_uid then
    raise exception 'not collaboration brand' using errcode = '42501';
  end if;
  if c.status <> 'awaiting_payment' then
    raise exception 'collaboration not awaiting payment' using errcode = '55000';
  end if;
  if c.amount_twd > 200000 then
    raise exception 'amount exceeds online payment limit' using errcode = '22023';
  end if;
  select count(*) into v_recent from public.payments p
   where p.collaboration_id = c.id and p.created_at > now() - interval '1 hour';
  if v_recent >= 10 then
    raise exception 'too many payment orders' using errcode = '54000';
  end if;

  -- KL + 台灣日期 YYMMDD + 12 位大寫十六進位 = 20 字（綠界 MerchantTradeNo 上限 20、英數字；測試商店是共用的，要夠亂）
  v_no := 'KL' || to_char(now() at time zone 'Asia/Taipei', 'YYMMDD')
          || upper(left(replace(gen_random_uuid()::text, '-', ''), 12));
  insert into public.payments
    (collaboration_id, provider, merchant_trade_no, amount_twd, payment_method, created_by)
  values (c.id, 'ecpay', v_no, c.amount_twd, p_method, v_uid);

  return query
  select p.merchant_trade_no, p.amount_twd, p.created_at
    from public.payments p where p.merchant_trade_no = v_no;
end;
$$;
revoke execute on function public.create_payment_order(uuid, text) from public, anon, authenticated, service_role;
grant execute on function public.create_payment_order(uuid, text) to authenticated;

-- 6. 付款成功：多了 p_env（驗證通知的金鑰屬於哪個環境）。
--    回傳 'paid'｜'already_paid'｜'paid_refund_required'｜'anomaly'。
--    找不到付款單、金額不符、付款單金額與合作案報價不符：記錄異常、回傳 'anomaly'（route 一樣回 1|OK，不讓綠界一直重送）。
--    status 為 'failed' 的付款單之後收到成功通知：照常改成 paid（綠界以最後的成功通知為準）。
drop function public.record_payment_success(text, integer, text, jsonb);
create function public.record_payment_success(
  p_merchant_trade_no text,
  p_amount_twd integer,
  p_provider_trade_no text,
  p_raw jsonb,
  p_env text default null
) returns text
language plpgsql security definer set search_path = '' as $$
declare
  p public.payments%rowtype;
  v_status public.collab_status;
  v_price integer;
  v_raw jsonb := public.payment_raw_whitelist(p_raw);
  v_ptn text := btrim(p_provider_trade_no);
begin
  if p_amount_twd is null then
    raise exception 'amount is required' using errcode = '22023';
  end if;
  if v_ptn is null or v_ptn = '' then
    raise exception 'provider_trade_no is required' using errcode = '22023';
  end if;
  if p_env is not null and p_env not in ('stage', 'prod') then
    raise exception 'invalid env' using errcode = '22023';
  end if;

  select * into p from public.payments where merchant_trade_no = p_merchant_trade_no for update;
  if not found then
    perform public.record_payment_anomaly('notify', 'unknown_trade_no', p_merchant_trade_no, v_ptn,
                                          null, null, null, p_amount_twd, v_raw);
    return 'anomaly';
  end if;
  if p.amount_twd <> p_amount_twd then
    perform public.record_payment_anomaly('notify', 'amount_mismatch', p_merchant_trade_no, v_ptn,
                                          p.id, p.collaboration_id, p.amount_twd, p_amount_twd, v_raw);
    return 'anomaly';
  end if;
  if p.status = 'paid' then
    return 'already_paid';
  end if;

  select c.status, c.amount_twd into v_status, v_price from public.collaborations c
   where c.id = p.collaboration_id for update;
  if p.amount_twd <> v_price then
    perform public.record_payment_anomaly('notify', 'price_mismatch', p_merchant_trade_no, v_ptn,
                                          p.id, p.collaboration_id, v_price, p_amount_twd, v_raw);
    return 'anomaly';
  end if;

  update public.payments
  set status = 'paid', provider_trade_no = v_ptn, paid_at = now(), raw_notify = v_raw,
      provider_env = coalesce(p_env, provider_env)
  where id = p.id;

  if v_status = 'awaiting_payment' then
    perform set_config('kollink.recording_payment', 'on', true);
    perform public.transition_collaboration(p.collaboration_id, 'mark_paid');
    perform set_config('kollink.recording_payment', 'off', true);
    return 'paid';
  end if;

  update public.payments set refund_required = true where id = p.id;
  insert into public.audit_logs
    (collaboration_id, actor_id, actor_kind, action, from_status, to_status, note)
  values
    (p.collaboration_id, null, 'system', 'payment_requires_refund', v_status, v_status,
     format('payment received while collaboration was %s; refund required', v_status));
  return 'paid_refund_required';
end;
$$;
revoke execute on function public.record_payment_success(text, integer, text, jsonb, text)
  from public, anon, authenticated, service_role;
grant execute on function public.record_payment_success(text, integer, text, jsonb, text) to service_role;

-- 7. ATM 取號結果（PaymentInfoURL）：記下銀行代碼、虛擬帳號、繳費期限給品牌看。
--    回傳 'recorded'｜'unchanged'｜'ignored'（已付款或不是 ATM 單）｜'anomaly'。
create function public.record_payment_info(
  p_merchant_trade_no text,
  p_provider_trade_no text,
  p_amount_twd integer,
  p_bank_code text,
  p_v_account text,
  p_expire_date date,
  p_raw jsonb
) returns text
language plpgsql security definer set search_path = '' as $$
declare
  p public.payments%rowtype;
  v_ptn text := btrim(p_provider_trade_no);
begin
  if p_amount_twd is null or v_ptn is null or v_ptn = '' or p_expire_date is null
     or p_bank_code is null or p_bank_code !~ '^[0-9]{3}$'
     or p_v_account is null or p_v_account !~ '^[0-9]{6,16}$' then
    raise exception 'invalid payment info' using errcode = '22023';
  end if;

  select * into p from public.payments where merchant_trade_no = p_merchant_trade_no for update;
  if not found then
    perform public.record_payment_anomaly('payment_info', 'unknown_trade_no', p_merchant_trade_no, v_ptn,
                                          null, null, null, p_amount_twd, p_raw);
    return 'anomaly';
  end if;
  if p.amount_twd <> p_amount_twd then
    perform public.record_payment_anomaly('payment_info', 'amount_mismatch', p_merchant_trade_no, v_ptn,
                                          p.id, p.collaboration_id, p.amount_twd, p_amount_twd, p_raw);
    return 'anomaly';
  end if;
  if p.status <> 'pending' or p.payment_method is distinct from 'atm' then
    return 'ignored';
  end if;
  if (p.atm_bank_code, p.atm_v_account, p.atm_expire_date)
     is not distinct from (p_bank_code, p_v_account, p_expire_date) then
    return 'unchanged';
  end if;

  update public.payments
  set atm_bank_code = p_bank_code, atm_v_account = p_v_account, atm_expire_date = p_expire_date,
      payment_info_at = now(), provider_trade_no = coalesce(provider_trade_no, v_ptn)
  where id = p.id;
  return 'recorded';
end;
$$;
revoke execute on function public.record_payment_info(text, text, integer, text, text, date, jsonb)
  from public, anon, authenticated, service_role;
grant execute on function public.record_payment_info(text, text, integer, text, text, date, jsonb) to service_role;

-- 8. 退款完成（實際退款在綠界廠商後台操作）：清除 refund_required、記錄時間與說明、寫 audit（payment_refunded）。
--    管理員（is_admin）或 service_role（Studio 的 README SQL；計畫 9 的後台）。
create function public.resolve_payment_refund(p_payment_id uuid, p_note text) returns void
language plpgsql security definer set search_path = '' as $$
declare
  v_uid uuid := auth.uid();
  v_actor text;
  v_note text := nullif(public.clean_text(p_note), '');
  p public.payments%rowtype;
  v_status public.collab_status;
begin
  if coalesce(auth.role(), '') = 'service_role'
     and coalesce(current_setting('role', true), '') = 'service_role' then
    v_actor := 'system';
  elsif public.is_admin() then
    v_actor := 'admin';
  else
    raise exception 'not admin' using errcode = '42501';
  end if;
  if v_note is null or char_length(v_note) > 500 or public.has_bidi(v_note) then
    raise exception 'invalid note' using errcode = '22023';
  end if;
  select * into p from public.payments where id = p_payment_id for update;
  if not found then
    raise exception 'payment not found' using errcode = 'P0002';
  end if;
  if not p.refund_required then
    raise exception 'refund not required' using errcode = '55000';
  end if;

  update public.payments
  set refund_required = false, refunded_at = now(), refund_note = v_note
  where id = p.id;

  select c.status into v_status from public.collaborations c where c.id = p.collaboration_id;
  insert into public.audit_logs
    (collaboration_id, actor_id, actor_kind, action, from_status, to_status, note)
  values
    (p.collaboration_id, case when v_actor = 'admin' then v_uid end, v_actor, 'payment_refunded',
     v_status, v_status, v_note);
end;
$$;
revoke execute on function public.resolve_payment_refund(uuid, text) from public, anon, authenticated, service_role;
grant execute on function public.resolve_payment_refund(uuid, text) to authenticated, service_role;

-- 9. 處理完一筆異常（例如在綠界後台確認後人工標記已付款或退款）：記錄時間與說明。
create function public.resolve_payment_anomaly(p_id bigint, p_note text) returns void
language plpgsql security definer set search_path = '' as $$
declare
  v_note text := nullif(public.clean_text(p_note), '');
  a public.payment_anomalies%rowtype;
begin
  if not ((coalesce(auth.role(), '') = 'service_role'
           and coalesce(current_setting('role', true), '') = 'service_role')
          or public.is_admin()) then
    raise exception 'not admin' using errcode = '42501';
  end if;
  if v_note is null or char_length(v_note) > 500 or public.has_bidi(v_note) then
    raise exception 'invalid note' using errcode = '22023';
  end if;
  select * into a from public.payment_anomalies where id = p_id for update;
  if not found then
    raise exception 'anomaly not found' using errcode = 'P0002';
  end if;
  if a.resolved_at is not null then
    raise exception 'anomaly already resolved' using errcode = '55000';
  end if;
  update public.payment_anomalies set resolved_at = now(), resolved_note = v_note where id = a.id;
end;
$$;
revoke execute on function public.resolve_payment_anomaly(bigint, text) from public, anon, authenticated, service_role;
grant execute on function public.resolve_payment_anomaly(bigint, text) to authenticated, service_role;
```

```ts
// 綠界設定只從伺服器端環境變數讀（絕不加 NEXT_PUBLIC_）。少任何一個、或組合不安全時回傳 null：
// 付款按鈕停用、通知 route 回 500（綠界會重送，設定補上後就能處理）。

export type EcpayEnv = "stage" | "prod";

export type EcpayConfig = {
  env: EcpayEnv;
  merchantId: string;
  hashKey: string;
  hashIV: string;
  /** 站台網址（只有 origin，例如 https://kollink.vercel.app），用來組 ReturnURL 等回呼網址 */
  siteUrl: string;
  checkoutUrl: string;
};

/** 綠界全方位金流 AioCheckOut V5（https://developers.ecpay.com.tw/?p=2862） */
export const ECPAY_CHECKOUT_URL: Record<EcpayEnv, string> = {
  stage: "https://payment-stage.ecpay.com.tw/Cashier/AioCheckOut/V5",
  prod: "https://payment.ecpay.com.tw/Cashier/AioCheckOut/V5",
};

/** 綠界公開的測試商店（https://developers.ecpay.com.tw/2856/）：金鑰是公開的，只能用在 stage。 */
export const ECPAY_STAGE_MERCHANT_ID = "3002607";

type Env = Record<string, string | undefined>;

export function readEcpayConfig(env: Env = process.env): EcpayConfig | null {
  const mode = env.ECPAY_ENV;
  if (mode !== "stage" && mode !== "prod") return null;
  const merchantId = env.ECPAY_MERCHANT_ID ?? "";
  const hashKey = env.ECPAY_HASH_KEY ?? "";
  const hashIV = env.ECPAY_HASH_IV ?? "";
  if (!/^[0-9]{1,10}$/.test(merchantId) || !hashKey || !hashIV) return null;
  // 正式模式不能用公開的測試商店（否則等於任何人都能偽造付款通知）
  if (mode === "prod" && merchantId === ECPAY_STAGE_MERCHANT_ID) return null;

  let url: URL;
  try {
    url = new URL(env.SITE_URL ?? "");
  } catch {
    return null;
  }
  const local = url.hostname === "localhost" || url.hostname === "127.0.0.1";
  if (url.protocol !== "https:" && !(mode === "stage" && local && url.protocol === "http:")) return null;
  if (url.pathname !== "/" || url.search || url.hash || url.username || url.password) return null;

  return { env: mode, merchantId, hashKey, hashIV, siteUrl: url.origin, checkoutUrl: ECPAY_CHECKOUT_URL[mode] };
}

export type PaymentAvailability = { enabled: boolean; env: EcpayEnv | null };

/** 給畫面用（不含金鑰）：能不能線上付款、是不是測試模式。 */
export function paymentAvailability(env: Env = process.env): PaymentAvailability {
  const c = readEcpayConfig(env);
  return c ? { enabled: true, env: c.env } : { enabled: false, env: null };
```

```ts
/**
 * 存進 payments.raw_notify／payment_anomalies.raw 的白名單。
 * 與 SQL public.payment_raw_whitelist 相同（改一邊要改另一邊）：不保存 card4no、card6no、ATMAccNo 等付款人資料。
 */
export const NOTIFY_FIELDS = [
  "MerchantID", "MerchantTradeNo", "StoreID", "RtnCode", "RtnMsg", "TradeNo", "TradeAmt",
  "PaymentDate", "PaymentType", "PaymentTypeChargeFee", "TradeDate", "SimulatePaid",
  "BankCode", "vAccount", "ExpireDate",
] as const;

export function pickNotifyFields(params: Record<string, string>): Record<string, string> {
  const out: Record<string, string> = {};
  for (const k of NOTIFY_FIELDS) if (Object.hasOwn(params, k)) out[k] = params[k].slice(0, 200);
  return out;
}

/** 付款單編號：與 payments.merchant_trade_no 的 check 相同。 */
export const MERCHANT_TRADE_NO_RE = /^[A-Za-z0-9]{1,20}$/;

/** 金額：純整數、1 起（不接受 4500.0、1e3、前後空白）。 */
export function parseTradeAmt(v: string | undefined): number | null {
  return /^[1-9]\d{0,8}$/.test(v ?? "") ? Number(v) : null;
}

export type AtmInfo = { bankCode: string; vAccount: string; expireDate: string };

/** ATM 取號結果：BankCode 3 碼、vAccount 6–16 碼數字、ExpireDate yyyy/MM/dd（可能帶時間）→ YYYY-MM-DD。 */
export function parseAtmInfo(params: Record<string, string>): AtmInfo | null {
  const bankCode = params.BankCode ?? "";
  const vAccount = params.vAccount ?? "";
  const m = /^(\d{4})\/(\d{2})\/(\d{2})(?: \d{2}:\d{2}(?::\d{2})?)?$/.exec(params.ExpireDate ?? "");
  if (!/^\d{3}$/.test(bankCode) || !/^\d{6,16}$/.test(vAccount) || !m) return null;
  const expireDate = `${m[1]}-${m[2]}-${m[3]}`;
  return isIsoDate(expireDate) ? { bankCode, vAccount, expireDate } : null;
}
```

```ts
import { todayTw } from "@/lib/briefs/dates";
import { RECENT_ORDER_MS } from "./limits";

/** payments 的可讀欄位（authenticated 讀不到 raw_notify、created_by、refund_note）。 */

  refund_required: boolean | null;
  created_at: string | null;

export type PaymentSummary = {
  /** 已付款的單裡有測試環境（stage）的：畫面標「測試付款」，管理員不能撥款 */
  testPaid: boolean;

  atm: AtmPending | null;

  recentCreditPending: boolean;
  /** 有需要退款、還沒處理的款項 */
  refundPending: boolean;
};

export const EMPTY_PAYMENT_SUMMARY: PaymentSummary = {
  testPaid: false, atm: null, recentCreditPending: false, refundPending: false,
};

/** rows 由新到舊。nowMs 由伺服器在 requireRole 之後算好傳進來。 */
export function summarizePayments(rows: PaymentRow[], nowMs: number): PaymentSummary {
  const today = todayTw(new Date(nowMs));
  const latest = rows[0];
  let atm: AtmPending | null = null;
  if (latest && latest.status === "pending" && latest.payment_method === "atm"
      && latest.atm_bank_code && latest.atm_v_account && latest.atm_expire_date
      && latest.atm_expire_date >= today && latest.amount_twd) {
    atm = { bankCode: latest.atm_bank_code, vAccount: latest.atm_v_account, expireDate: latest.atm_expire_date, amount: latest.amount_twd };
  }
  const created = latest?.created_at ? Date.parse(latest.created_at) : NaN;
  return {
    testPaid: rows.some((r) => r.status === "paid" && r.provider_env === "stage"),
    atm,
    recentCreditPending: !!latest && latest.status === "pending" && latest.payment_method === "credit"
      && !Number.isNaN(created) && nowMs - created < RECENT_ORDER_MS,
    refundPending: rows.some((r) => r.refund_required === true),
  };
}

export function atmDeadlineLabel(date: string): string {
```

```ts
import { verifyCheckMacValue } from "./ecpay";
import { MERCHANT_TRADE_NO_RE, parseTradeAmt, pickNotifyFields } from "./notify-fields";

export type RecordPaymentResult = "paid" | "already_paid" | "paid_refund_required" | "anomaly";

export interface EcpayNotifyDeps {
  hashKey: string;
  hashIV: string;
  merchantId: string;
  /** 驗證通知用的是哪一組金鑰：stage 才接受 SimulatePaid=1 */
  env: "stage" | "prod";
  recordPaymentSuccess(input: {
    merchantTradeNo: string;
    amountTwd: number;
    providerTradeNo: string;
    raw: Record<string, string>;
    env: "stage" | "prod";
  }): Promise<RecordPaymentResult>;
  logError(message: string, meta?: Record<string, unknown>): void;
}

/**
 * 付款結果通知（ReturnURL，https://developers.ecpay.com.tw/?p=2878）。
 * 驗簽與 MerchantID 不符回 400（綠界會重送，但重送也不會過，只留 log）；
 * 其他情況（成功、重複、需退款、異常、付款失敗）一律 1|OK，避免綠界重送；記錄失敗回 500 讓綠界重送。
 */
export async function handleEcpayNotify(
  params: Record<string, string>,
  deps: EcpayNotifyDeps,
): Promise<{ status: number; body: string }> {
  const merchantTradeNo = (params.MerchantTradeNo ?? "").slice(0, 64);

  if (!verifyCheckMacValue(params, deps.hashKey, deps.hashIV)) {
    deps.logError("ecpay notify: bad CheckMacValue", { merchantTradeNo });
    return { status: 400, body: "0|CheckMacValue Error" };
  }

  if (params.MerchantID !== deps.merchantId) {
    deps.logError("ecpay notify: merchant mismatch", { merchantTradeNo });
    return { status: 400, body: "0|MerchantID Error" };
  }

  if (!MERCHANT_TRADE_NO_RE.test(merchantTradeNo)) {
    deps.logError("ecpay notify: bad MerchantTradeNo", { merchantTradeNo });
    return { status: 400, body: "0|Bad MerchantTradeNo" };
  }

  // 模擬付款（綠界廠商後台「模擬付款」）不是真的收到錢：正式環境一律忽略；測試環境照常記錄（測試 ATM 只能靠它）
  if (params.SimulatePaid === "1" && deps.env !== "stage") {
    deps.logError("ecpay notify: simulated payment ignored", { merchantTradeNo });
    return { status: 200, body: "1|OK" };
  }

  if (params.RtnCode !== "1") {
    deps.logError("ecpay notify: payment not successful", {
      merchantTradeNo,
      rtnCode: (params.RtnCode ?? "").slice(0, 16),
    });
    return { status: 200, body: "1|OK" };
  }

  const amountTwd = parseTradeAmt(params.TradeAmt);
  if (amountTwd === null) {
    deps.logError("ecpay notify: bad TradeAmt", {
      merchantTradeNo,
      tradeAmt: (params.TradeAmt ?? "").slice(0, 32),
    });
    return { status: 400, body: "0|Bad TradeAmt" };
  }

  const providerTradeNo = (params.TradeNo ?? "").trim();
  if (!providerTradeNo) {
    deps.logError("ecpay notify: missing TradeNo", { merchantTradeNo });
    return { status: 400, body: "0|Missing TradeNo" };
  }

  try {
    const result = await deps.recordPaymentSuccess({
      merchantTradeNo,
      amountTwd,
      providerTradeNo,
      raw: pickNotifyFields(params),
      env: deps.env,
    });
    if (result === "paid_refund_required") {
      deps.logError("ecpay notify: payment requires refund", { merchantTradeNo });
    } else if (result === "anomaly") {
      deps.logError("ecpay notify: payment anomaly recorded", { merchantTradeNo, amountTwd });
    }
    return { status: 200, body: "1|OK" };
  } catch (error) {
    deps.logError("ecpay notify: record failed", { merchantTradeNo, error: String(error) });
    return { status: 500, body: "0|Error" };
  }
}
```

```ts
  merchantId: string;
  recordPaymentInfo(input: {
    merchantTradeNo: string;
    providerTradeNo: string;
    amountTwd: number;
    bankCode: string;
    vAccount: string;
    expireDate: string;
    raw: Record<string, string>;
  }): Promise<RecordPaymentInfoResult>;
  logError(message: string, meta?: Record<string, unknown>): void;
}

/**
 * ATM 取號結果通知（PaymentInfoURL，https://developers.ecpay.com.tw/?p=2881）。
 * RtnCode=2 才是取號成功；其他代碼回 1|OK 並留 log（取號失敗時品牌重新付款即可）。
 * 這個通知不代表已付款：付款後綠界另外打 ReturnURL。
 */
export async function handleEcpayPaymentInfo(
  params: Record<string, string>,
  deps: EcpayPaymentInfoDeps,
): Promise<{ status: number; body: string }> {
  const merchantTradeNo = (params.MerchantTradeNo ?? "").slice(0, 64);

  if (!verifyCheckMacValue(params, deps.hashKey, deps.hashIV)) {
    deps.logError("ecpay payment-info: bad CheckMacValue", { merchantTradeNo });
    return { status: 400, body: "0|CheckMacValue Error" };
  }
  if (params.MerchantID !== deps.merchantId) {
    deps.logError("ecpay payment-info: merchant mismatch", { merchantTradeNo });
    return { status: 400, body: "0|MerchantID Error" };
  }
  if (!MERCHANT_TRADE_NO_RE.test(merchantTradeNo)) {
    deps.logError("ecpay payment-info: bad MerchantTradeNo", { merchantTradeNo });
    return { status: 400, body: "0|Bad MerchantTradeNo" };
  }
  if (params.RtnCode !== "2") {
    deps.logError("ecpay payment-info: not an ATM number", {
      merchantTradeNo,
      rtnCode: (params.RtnCode ?? "").slice(0, 16),
    });
    return { status: 200, body: "1|OK" };
  }

  const amountTwd = parseTradeAmt(params.TradeAmt);
  const providerTradeNo = (params.TradeNo ?? "").trim();
  const info = parseAtmInfo(params);
  if (amountTwd === null || !providerTradeNo || !info) {
    deps.logError("ecpay payment-info: bad fields", { merchantTradeNo });
    return { status: 400, body: "0|Bad PaymentInfo" };
  }

  try {
    const result = await deps.recordPaymentInfo({
      merchantTradeNo, providerTradeNo, amountTwd, ...info, raw: pickNotifyFields(params),
    });
    if (result === "anomaly") deps.logError("ecpay payment-info: anomaly recorded", { merchantTradeNo, amountTwd });
    return { status: 200, body: "1|OK" };
  } catch (error) {
    deps.logError("ecpay payment-info: record failed", { merchantTradeNo, error: String(error) });
    return { status: 500, body: "0|Error" };
  }
}
```

```ts
export type StartPaymentResult = { ok: true; form: CheckoutForm } | { ok: false; error: string };
type PaymentOrderRow = { merchant_trade_no: string | null; amount_twd: number | null; created_at: string | null };

// "use server" 檔案只能 export async 函式：常數不 export
const PAYMENT_UNAVAILABLE = "線上付款尚未開放，請聯絡平台";

/**
 * 「確認並付款」：以品牌自己的 client 呼叫 create_payment_order（資料庫檢查身分、狀態、金額、頻率，並產生付款單編號），
 * 再由伺服器組好綠界表單與 CheckMacValue 回傳；瀏覽器只負責把表單 POST 到綠界。金鑰不會離開伺服器。
 * 每次都建立新的付款單（綠界不接受重複的 MerchantTradeNo）。
 */
export async function startPaymentAction(collabId: unknown, method: unknown): Promise<StartPaymentResult> {
  await requireRole("brand");
  if (!isUuid(collabId) || !isPaymentMethod(method)) return { ok: false, error: BAD_INPUT };
  const config = readEcpayConfig();
  if (!config) return { ok: false, error: PAYMENT_UNAVAILABLE };

  const supabase = await createClient();
  const { data, error } = await supabase.rpc("create_payment_order", { p_collab_id: collabId, p_method: method });
  if (error) return { ok: false, error: collabErrorMessage(error) };
  const row = ((data ?? []) as unknown as PaymentOrderRow[])[0];
  const createdAt = row?.created_at ? new Date(row.created_at) : null;
  if (!row?.merchant_trade_no || !row.amount_twd || !createdAt || Number.isNaN(createdAt.getTime())) {
    return { ok: false, error: "發生錯誤，請稍後再試" };
  }
  return {
    ok: true,
    form: buildCheckoutForm({
      config, merchantTradeNo: row.merchant_trade_no, amountTwd: row.amount_twd, method, collabId, createdAt,
    }),
  };
}
```

```tsx
/**
 * 選付款方式 →「前往付款」：Server Action 建單並回傳綠界表單（含 CheckMacValue），
 * 這裡渲染成隱藏表單後立刻 submit（整頁 POST 到綠界）。
 */
function PayForm({ collabId, payment }: { collabId: string; payment: PaymentAvailability }) {
  const [method, setMethod] = useState<PaymentMethod>("credit");
  const [form, setForm] = useState<CheckoutForm | null>(null);
  const [error, setError] = useState<string | null>(null);
  const [pending, startTransition] = useTransition();
  const formRef = useRef<HTMLFormElement>(null);
  const name = useId();

  useEffect(() => {
    if (form) formRef.current?.submit();
  }, [form]);

  if (!payment.enabled) {
    return (
      <div className="space-y-2">
        <button type="button" disabled className={primary}>確認並付款</button>
        <p role="status" className="text-sm text-muted">
          線上付款尚未開放。目前由平台人工確認款項，確認後會自動進入交稿階段。
        </p>
      </div>
    );
  }

  function start() {
    setError(null);
    startTransition(async () => {
      try {
        const res = await startPaymentAction(collabId, method);
        if (res.ok) setForm(res.form);
        else setError(res.error);
      } catch {
        setError("發生錯誤，請稍後再試");
      }
    });
  }

  const busy = pending || form !== null;
  return (
    <div className="space-y-3">
      <fieldset className="space-y-2">
        <legend className="text-sm font-semibold text-ink">付款方式</legend>
        {METHODS.map((m) => (
          <label key={m.value} className="flex items-start gap-2 text-sm text-ink">
            <input
              type="radio" name={name} value={m.value} checked={method === m.value} disabled={busy}
              onChange={() => setMethod(m.value)} className="mt-1 accent-ink"
            />
            <span>
              <span className="font-semibold">{m.label}</span>
              <span className="block text-muted">{m.hint}</span>
            </span>
          </label>
        ))}
      </fieldset>
      <button type="button" disabled={busy} onClick={start} className={primary}>
        {busy ? "前往綠界付款頁…" : "確認並付款"}
      </button>
      {error && <p role="alert" className="text-sm text-danger">{error}</p>}
      {form && (
        <form ref={formRef} method="post" action={form.action} acceptCharset="UTF-8" className="hidden">
          {Object.entries(form.fields).map(([k, v]) => <input key={k} type="hidden" name={k} value={v} />)}
        </form>
      )}
    </div>
  );
}
```

````markdown
SQL 都要**整段一起執行**（`begin` 到 `commit`），只改 `填入…` 的地方，直接複製、不要手打。案號格式不對或找不到剛好一個合作案時會報錯，整段不會生效。

**標記已付款**（`awaiting_payment` → `awaiting_submission`）。和綠界走同一條路：先建付款單，再呼叫 `record_payment_success`（不要直接改狀態，資料庫也不允許）：
```sql
begin;
set local role service_role;
select set_config('request.jwt.claims', '{"role":"service_role"}', true);
select set_config('kollink.case_code', lower('填入案號'), true);
do $$
declare
  v_code text := current_setting('kollink.case_code');
  v_n integer;
begin
  if v_code !~ '^[0-9a-f]{8}$' then
    raise exception '案號格式不對：%', v_code;
  end if;
  select count(*) into v_n from public.collaborations c where c.id::text like v_code || '%';
  if v_n <> 1 then
    raise exception '案號 % 找到 % 個合作案，請確認', v_code, v_n;
  end if;
end;
$$;
insert into public.payments (collaboration_id, provider, merchant_trade_no, amount_twd)
select c.id, 'ecpay', 'MAN' || upper(left(md5(random()::text), 17)), c.amount_twd
  from public.collaborations c
 where c.id::text like current_setting('kollink.case_code') || '%' and c.status = 'awaiting_payment';
select p.merchant_trade_no,
       public.record_payment_success(p.merchant_trade_no, p.amount_twd, 'MANUAL-' || p.merchant_trade_no,
                                     '{"source":"manual"}'::jsonb) as result
  from public.payments p
  join public.collaborations c on c.id = p.collaboration_id
 where c.id::text like current_setting('kollink.case_code') || '%' and p.status = 'pending'
   and p.merchant_trade_no like 'MAN%';
select c.status from public.collaborations c where c.id::text like current_setting('kollink.case_code') || '%';
commit;
```
`result` 是 `paid`、最後的 `status` 是 `awaiting_submission` 就完成了。沒有任何列：合作案已經不是「等待付款」。

### 撥款

**撥款**（`awaiting_payout` → `completed`）。測試付款（綠界測試環境）沒有實際收款，會被拒絕：
```sql
begin;
set local role service_role;
select set_config('request.jwt.claims', '{"role":"service_role"}', true);
select set_config('kollink.case_code', lower('填入案號'), true);
do $$
declare
  v_code text := current_setting('kollink.case_code');
  v_n integer;
begin
  if v_code !~ '^[0-9a-f]{8}$' then
    raise exception '案號格式不對：%', v_code;
  end if;
  select count(*) into v_n from public.collaborations c where c.id::text like v_code || '%';
  if v_n <> 1 then
    raise exception '案號 % 找到 % 個合作案，請確認', v_code, v_n;
  end if;
  if exists (select 1 from public.payments p join public.collaborations c on c.id = p.collaboration_id
              where c.id::text like v_code || '%' and p.status = 'paid' and not p.refund_required
                and p.provider_env = 'stage') then
    raise exception '案號 % 的款項是綠界測試環境的付款（沒有實際收款），不能撥款', v_code;
  end if;
end;
$$;
select c.id, public.transition_collaboration(c.id, 'payout', '人工撥款') as result
  from public.collaborations c
 where c.id::text like current_setting('kollink.case_code') || '%' and c.status = 'awaiting_payout';
commit;
```
`result` 是 `completed` 就結案了（實際轉帳在平台外處理）。

### 退款（只記錄，實際退款在綠界後台）

合作案取消後才到款、或同一個合作案付了兩次時，資料庫會標記「需退款」，雙方的事件看到「收到一筆額外的付款，平台會處理退款」。

**需要退款的款項**：
```sql
select p.id as 付款單, left(c.id::text, 8) as 案號, p.merchant_trade_no as 綠界訂單編號,
       p.provider_trade_no as 綠界交易編號, p.amount_twd as 金額, p.payment_method as 方式,
       p.provider_env as 環境, p.paid_at at time zone 'Asia/Taipei' as 付款時間, c.status as 合作案狀態
  from public.payments p
  join public.collaborations c on c.id = p.collaboration_id
 where p.refund_required
 order by p.paid_at;
```

在綠界廠商後台用「綠界訂單編號」找到交易辦理退款（信用卡可以刷退；ATM 無法原路退回，要向品牌取得帳號另外轉帳），完成後**處理退款**（`填入付款單` 換成上面查到的付款單 id，`填入說明` 寫退款方式與日期）：
```sql
begin;
set local role service_role;
select set_config('request.jwt.claims', '{"role":"service_role"}', true);
select public.resolve_payment_refund('填入付款單'::uuid, '填入說明');
commit;
```
沒有錯誤就完成了，雙方的事件會多一筆「平台已退回一筆額外的付款」。`refund not required`：這筆已經處理過。

### 付款異常

金額不符、找不到付款單等異常不會讓綠界一直重送，而是記下來（Vercel log 也有 `ecpay notify: payment anomaly recorded`）。合作案的事件顯示「平台正在確認一筆付款」。

**付款異常**：
```sql
select a.id as 異常, a.created_at at time zone 'Asia/Taipei' as 時間, a.source as 來源, a.kind as 類型,
       a.merchant_trade_no as 綠界訂單編號, a.provider_trade_no as 綠界交易編號,
       a.expected_amount_twd as 應付, a.received_amount_twd as 實收, left(a.collaboration_id::text, 8) as 案號
  from public.payment_anomalies a
 where a.resolved_at is null
 order by a.created_at;
```
````
